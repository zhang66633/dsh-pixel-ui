# 踩坑记录

> 只记「会再犯 + 有复现条件」的坑。编号递增。

## #1 cordis 事件总线是全树共享的平铺表 → 注册期的 publish 会污染恢复逻辑（v1.4.0 修复，根因级）

**现象**：first-run（localStorage 空、宿主无偏好文件）时像素皮肤不激活，UI 停在宿主内置外观；v1.3.0 起就存在，09-28 会话里表现为「loader 树里有 include:dsh-pixel-ui，但证不了渲染结果」。

**根因（已查实，非推测）**：
1. `@deepseek-ai/cordis` 的 `Context` 构造器为**每个** context `new EventsService(self)`（src/context.ts:80），但 `extend()` 用 `Object.create(this)` 原型继承（src/context.ts:101）——插件 fiber 的子 ctx 与根 ctx 共享**同一个** `_hooks` 平铺表（src/events.ts:132）。兄弟插件 `ctx.emit` 对方收得到。
2. `ThemeRuntime.register()` 内部调用 `publish()` → `ctx.emit('theme/change')`（ui-theme lib/client.js:1450/1518）。pixel 插件 apply 里先 `ctx.on('theme/change')` 再注册四个主题，于是**注册阶段就连收 4 次 change**，此时 preference 还是宿主内置值（如 profile patch 写死的 `light`）。
3. 旧监听器对这些事件的处置是「非像素偏好 → `storeWanted(pref)`」，把 `light` 写进了 localStorage。随后的恢复逻辑读到这个**被自己污染的值**，`RESTORABLE_IDS.has('light')` 为真 → `setTheme('light')` → 现代 UI。

**规避（v1.4.0 起）**：
- 监听器的内置偏好分支增加 `want === null` 早退：**没有任何记忆时，内置偏好到来只是宿主初始状态，不记录**（注册期 publish、首次 adopt 都属于这一类）。
- 读取边界归一化：`readLocalTheme()` 只返回 `RESTORABLE_IDS` 内的值，垃圾值/旧 id 一律视为无记忆。
- 回归测试：`scripts/test-client.mjs` 的 "first run: default pixel-wood" 与 "garbage local value treated as first run" 两条，以及 fake ThemeRuntime 在 register() 时忠实 publish。

**通用教训**：插件 apply 阶段若注册「会在注册期被触发」的事件监听器，必须假设监听器会在自身初始化完成前就被调用；「把中间状态当成用户意图写持久层」是这类 bug 的通用形状。

## #2 DSH app.asar 是「头部 JSON」布局，不是标准尾部 pickle（v1.4.0 查契约用）

**现象**：按标准 asar（末尾 8 字节 pickle）读 `D:\_Downloads\Installers\dsh\resources\app.asar`，`tail[0]=1952984892` 明显不是 header 尺寸，读 offset 16 附近当 header 会 hang（分配 1.9GB buffer）。

**实际布局（实测）**：
```
[0:4]   uint32 = 4（pickle 标记）
[4:8]   uint32 = 总长类字段（3392056）
[8:12]  uint32 = 3392052
[12:16] uint32 = header JSON 长度（3392048）
[16:16+jsonLen] {"files": {...}}（文件树，含每文件 size/offset/integrity）
[之后]  第二个 JSON {schemaVersion, release, ...}
[再往后] 文件数据，偏移相对 16+jsonLen
```

**工具**：`D:\Mid\_asar_tool\asar3.cjs`（`list <substr>` / `cat <path> <outfile>`），按上述布局解析。注意 unpacked 文件要走 `app.asar.unpacked` 目录。

**附带坑（powerShell + node）**：本环境 `node script.cjs ... | Select-Object -First N` 会挂起；先重定向到文件再读。另 `new URL('rel', 'D:\\path\\')` 抛 `ERR_INVALID_URL`（Windows 路径不是合法 base）——用 `join()`/`pathToFileURL()`。

## #3 ESM 测试里解析宿主 peer 包（v1.4.0 测试链）

**现象**：`lib/index.js` import `@deepseek-ai/dsh-home-paths`，在仓库自身 node_modules 里没有 → `ERR_MODULE_NOT_FOUND`；直接 `new URL(spec, 'C:/.../node_modules/')` 又报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`（缺 `file://`）与 `ERR_UNSUPPORTED_DIR_IMPORT`（ESM 不做目录/exports 解析）。

**解法**：`scripts/resolve-dsh-peers.mjs`（`node:module` 的 register hook）：先按项目自身解析，失败则读 `$DSH_TEST_PEER_MODULES`（默认本机 profile node_modules）下包的 package.json `main`，转 `pathToFileURL` 后再交给 next。ESM 的目录导入不读 exports 映射，只能自己读 main。

## #4 fake ctx.effect 的保真度（v1.4.0 测试链）

**现象**：fake `effect(fn){ effects.push({dispose: fn()}) }` 让 locale 注册那种无返回值的 effect 的 dispose 变成 undefined，dispose 阶段炸 `effect.dispose is not a function`；改成 dispose 再调 fn() 又会**重跑** effect。

**正解**：注册时跑 fn、把返回值记为 cleanup；dispose 只调 cleanup（可为 undefined）。真实 cordis 的 `ctx.effect` 永远返回 disposer，与 effect 函数自身返回什么无关。

## #5 运行中宿主的热更新边界（v1.4.0 上线注意）

- **client 半边**：改 `lib/client.js` 后浏览器刷新即生效（boot manifest  entry 带 rev 哈希，bundle 变化会触发重载）——link 安装下无需重启 dsh。
- **node 半边**：路由在宿主启动时注册，**必须重启 DSH Desktop** 才生效；旧宿主上新路由 404，客户端 fetch 已降级（本地镜像照常）。
- 验证 node 半边存活的最小手段：直连当前端口打 `/dsh-pixel-ui/fonts/<file>`（无需鉴权），比 `--dump-config` 轻。

## #6 「伪像素」的三条来源（v1.5.0 重写，桌面端实测）

用户原话：「整体优化，改善那种伪像素（比如任务那一长条，内部一大堆线），使其趋近于真实像素质感」。

**来源 1：半透明 inset/outset 阴影**。v1.4 的立体感全靠
`box-shadow: inset 1px 1px 0 rgba(255,255,255,0.22), inset -1px -1px 0 rgba(0,0,0,0.5)`
这类半透明层。1px 的偏移叠加 alpha 混合，在 **1.25 DPR**（本机 1920×1200 @125%）上落在
1.25 个物理像素处 → 浏览器抗锯齿补一列灰 → 整圈毛边。像素风只认**实色**：
`inset 0 2px 0 <实色亮>` / `inset 0 -2px 0 <实色暗>`，或者干脆不要立体。

**来源 2：1px 细渐变纹理**。任务条/进度条用 `repeating-linear-gradient` 铺 1px 竖线，
在非整数缩放下同样每两条糊一条，远看是「一大堆线」的噪点。改成 **2px 方块**、
或直接平涂 + 一档明度差。

**来源 3：`[class*=...]` 子串选择器**。v1.4 用
`html[data-pixel-ui] [class*='card'] { border: 2px solid ... }`
一类规则做「卡片/面板/页签」质感，实际命中了宿主大量它没打算命中的元素：
`.xz4KEq_frame` 含 `frame`、`.Dc7zOa_headerActions` 含 `header`、图标类含 `message`……
结果整个界面被盖上一层厚重黑框，用户第二次报的就是「**凹陷了**」。
**规避**：皮肤只允许三类选择器——HTML 语义（button/input/pre/table…）、
稳定 ARIA/data 属性（`[role=tab]`、`[aria-selected]`）、本插件自己的 `.px-*`。
`scripts/test-client.mjs` 有一条门禁断言，禁止无前缀的 `[class*=...]` 复活。

**用户决策（2026-10-01）**：不要任何立体效果。所以 v1.5.0 的样式表里
**一个 `box-shadow` / `text-shadow` 都没有**（同样由测试断言守住），层次只靠
整像素描边 + 平涂色块 + 2px 棋盘抖动（`--px-dither`）+ 手绘 SVG 像素图形。

## #7 桌面端「一半一半」：宿主把 `--dsh-conversation-column-width` 写死成 0（v1.5.0 修复）

**现象**：DSH Desktop 窗口拉宽后，聊天正文仍只占左侧约 1/3，右侧一大片空背景；
页签、轨迹、记忆也挤在左边（用户原话「一半一半」）。

**根因（源码级）**：`@deepseek-ai/dsh-client-ui-conversation` 的
`.Dc7zOa_body` 声明

```css
--dsh-chat-content-width: var(--dsh-chat-user-width,
  clamp(680px, calc(var(--dsh-conversation-column-width, 0px) * .64), 920px));
```

而 **`--dsh-conversation-column-width` 全仓（app.asar 全部 client 包）只有这一处引用、
没有任何赋值**（`grep -a` 扫过 121MB 的 app.asar 确认）。于是 clamp 恒取
**680px 下限**，宽屏上正文永远是 680px；宿主自己的 `margin: 0 auto` 仍在，
所以看起来是「居中一窄条 + 两侧空」。

**修法**：皮肤在**根作用域**补上缺的值，并用 `!important`（宿主会把
`--dsh-chat-user-width` 以内联样式写在容器上，只有 `!important` 压得过内联）：

```css
html[data-pixel-ui] {
  --dsh-conversation-column-width: calc(100vw - 280px) !important;
  --dsh-chat-user-width: var(--px-chat-width) !important;   /* clamp(680px, 64vw-140px, 1200px) */
}
```

**实测验证（本机 DSH Desktop 0.2.0-rc.2，需 `--dsh-chat-content-width` 生效）**：
在 `lib/client.js` 里挂一个临时探针（把结果写进 `document.title` / DOM 文本），
1920×1200 @125% 全屏窗口下量到 `col=843|scroll=1241|vw=1536`
（此前恒为 `col=680`）。探针手法见 `TEMP/probe.mjs`（不入库）：
- Renderer 跑的是 `dsh-app://app/`，**DevTools 的 Console 是唯一能执行 JS 的入口**；
  但它不带 `--remote-debugging-port`，CDP 连不上。
- 读回结果别用 UIA：Chromium 的 UIA 树默认**不**为这个页面构建（只暴露 13~19 个壳节点）。
  可行路径有两条：① 文本写进 `document.title` → OS 窗口标题可直接读；
  ② 页面里插一个带文字的元素 → 截图后交给视觉模型读。

## #8 桌面端 renderer 是 `dsh-app://app/`，相对路径 fetch 到不了宿主 HTTP 路由（v1.5.0 修复）

**现象**：宿主偏好文件里明明写着 `pixel-paper`，页面刷新后皮肤却不激活；
DevTools 里 `document.documentElement.dataset.pixelUi === null`，但
`style[data-plugin=dsh-pixel-ui]` 存在（样式表注入了 = 插件跑了）。

**根因**：客户端恢复逻辑读「宿主侧偏好」时用的是
`fetch('/dsh-pixel-ui/preference')`。桌面端页面 origin 是 `dsh-app://app`，
相对 URL 落到该 scheme 上，宿主 HTTP 服务（127.0.0.1:随机端口）根本不在链路上
→ 请求失败 → 恢复逻辑拿不到记忆，只能回落到 `readLocalTheme()`，而
`localStorage` 又跟着 origin 走（`dsh-app://` 与 `http://127.0.0.1:<port>` 是两份）。

**修法**：宿主半边用 **index 注入**把偏好直接写进页面启动数据
（`ctx.on('webserver/index-inject', table => table.push({ kind:'global', name:'__DSH_PIXEL_UI__', value:{ theme } }))`），
客户端优先读 `globalThis.__DSH_PIXEL_UI__.theme`，读不到再走 HTTP 路由（Web 部署那条路）。
注入是「在第一次绘制前就存在」的，所以还顺手消掉了首屏闪现代皮的那一帧。

**附带坑**：`Restoring` 标志不能在「异步读取宿主偏好完成」时才放掉——
宿主自己的初始 preference（设置作用域加载、主题注册时的 publish）会在这个窗口里到达，
被当成「用户真选了现代默认」而丢弃皮肤。正确时序是**应用完目标皮肤再放标志**。

## #9 投稿 awesome-dsh-plugin 的两条会静默烂掉的约定（v1.5.0 投稿时核对）

来源：[contributing.md](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md)。

**① 截图必须声明在「插件自己仓库」的 `screenshots.json`**，不是列表仓库。
列表仓库的 `data/screenshots.json` 只是早期条目的回退，文档明令「不要再往里面加新的键」。
放自己仓库的好处是换图只推自己的仓库、下次构建自动生效；反过来，写在对方仓库里的
绝对 URL 会静默腐烂——已发布的 773 张截图里 41 张就是这样变成 404 的。
规则：1–8 张、相对路径不得以 `/` 开头也不得含 `..`、绝对 URL 只收 GitHub 托管的 https。

**② `tarball:` 用 `latest/download/` 时，资产名不能带版本号。**
`latest` 是请求时解析的，但文件名是**照字面取**的：

```
tarball: .../releases/latest/download/dsh-pixel-ui.tgz        # ✅ 永不烂
tarball: .../releases/latest/download/dsh-pixel-ui-1.5.0.tgz  # ❌ 下次发版当天起 404
tarball: .../releases/download/v1.5.0/dsh-pixel-ui-1.5.0.tgz  # ✅ 钉 tag，带版本号也安全
```

**本仓库的选择**：每次发版**同时上传两个资产名**——`dsh-pixel-ui-<ver>.tgz`（给人看、给钉 tag 用）
与 `dsh-pixel-ui.tgz`（无版本，给 `latest/download/` 用）。所以发版清单多一条：
`gh release upload <ver> TEMP/dsh-pixel-ui.tgz`，漏了这一步列表里的下载链接就会指向旧包。

**投稿门槛核对（本仓库实测）**：`dsh.bundle.patch` 声明 + `cordis.patch.yml` 在根 ✅；
`dsh-plugin` topic ✅；仓库创建满 1 天 ✅；官方包走 `peerDependencies` 且**带显式
prerelease 分支**（文档里那个 `ERESOLVE` 坑我们没踩）✅；分类必须是 `theme` 才会进
dsh-market 的主题 Tab ✅。

## #10 DSH 0.2.1-rc.3 的四个兼容坑（v1.5.1）

**① `>=0.2.0-rc.1 <0.3.0-0` 在默认预发布门禁下不匹配 `0.2.1-rc.3`。**
node-semver 的规则是「版本带 prerelease 时，比较器集合里必须有一个**同一
major.minor.patch** 且带 prerelease 的比较器」。`>=0.2.0-rc.1` 的 tuple 是 0.2.0，
`<0.3.0-0` 是 0.3.0，都比不过 0.2.1。实测：

```
satisfies('0.2.1-rc.3', '>=0.2.0-rc.1 <0.3.0-0', {includePrerelease:true})  // true
satisfies('0.2.1-rc.3', '>=0.2.0-rc.1 <0.3.0-0')                          // false
```

app-boot 与 dshmarket 都开 `includePrerelease:true`，所以能过；但 pnpm 的 peer 解析
不开。**规避**：peer / engines 里显式补 `>=0.2.1-0 <0.3.0-0`。

**② app-boot 在 `engines.dsh` 存在时不再看 peers。**
0.2.1 的 `evaluatePluginCompatibility` 先读 `engines.dsh`，有就单独决定、直接忽略
`peerDependencies`。只写 peers 的包在老判定器里没问题，在新判定器里等于没声明
`engines`；两个都写才稳（dshmarket 的发现页也是 engines ∩ peers）。

**③ `dsh-client-store` / `dsh-client-ui-slots` 不再是 `node_modules` 包。**
0.2.1 把它们放进 Web 前端的静态模块表（`PLATFORM_MODULES`），app.asar 的
`node_modules/@deepseek-ai` 里搜不到目录。插件 bundle 仍按同名 `require`，由模块表
提供；**不要**因为目录不存在就加 `dsh.client.external`（那会要求一个不存在的 graph row）。
`dsh.client.inject` 里的包名顺序照旧。

**④ dshmarket 读的是 npm `latest`，不是本地 `package.json`。**
本地 link 安装的 1.5.1 即使声明齐全，发现页仍会按 npm 上的旧版判定。要让市场卡片
显示 compatible，必须发布一个带 engines/peers 的版本（本次已发 1.5.1 到 npmjs）。
发布后还要清掉 `.dsh-market/discovery-compatibility-v1.json` 里的旧 facts，否则
24h TTL 内仍按旧 manifest 算。另：desktop shell 的 index 注入表在进程启动时取得，改
`$DSH_HOME/storages/dsh-pixel-ui/preference.json` 后仅 F5 可能读到旧 bootstrap，
需要整窗重启才会应用新偏好。

## #11 像素动效的五个坑（v1.6.0）

**① `border-left` 加在宿主的 shimmer decoration 上会重影。**
宿主 `[data-shimmer]` 的结构是「正文 + 绝对定位的复制文本 decoration」。给
decoration 加 2px border 会把复制文本右移 2px，和正文错位，看起来像重影。
用 `background-image` 画 2px 竖条，不参与布局。

**② reduced-motion 的 `*` 管不到伪元素。**
`html[data-pixel-ui] * { transition:none !important }` 对 `[role=tab]::after` 无效；
v1.6.0 第一版探针在 `--force-prefers-reduced-motion` 下仍读到
`transform 0.14s steps(4)`。必须补 `*::before, *::after`。

**③ 页签下划线不要用 `background-size` 叠在透明 border 上。**
`border-bottom: 3px solid transparent` + `background-clip: border-box` 会留下一条
1–4px 的缝（取决于 padding），线看起来是浮着的。用 `::after` 定位 `bottom:-3px`
盖住 border，和分隔线齐平。

**④ 勾/点颜色必须按主题换。**
纸面主题的 `--px-gold` 是深金 `#A07000`，深木色勾 `#1A0F06` 对比度只有 ~2:1，
看起来像一个纯色方块。把 SVG 做成 `--px-check` / `--px-radio` 变量，纸面用
`#FFFDF5`，其余主题保持深色。

**⑤ 主按钮的 hover 不能被 generic hover 刷成木色。**
v1.5.0 的 `button:hover { background-color: wood-dark !important }` 会覆盖宿主
primary hover，深字落深底。v1.6.0 把 generic hover 排除
`[class*=primary]` / `[class*=danger]`，主按钮走自己的
`--dsw-alias-button-primary-hover` 与 dither。

**⑥ 会话行不是 button，选中态的 background 会盖掉 hover。**
宿主 workspace 的会话/项目行是 `div[role=treeitem]`，不是 `button`/`a`；
选中行用 `[aria-selected=true]` 的 `background`，我们的 selected 规则写在
`:hover` 之后，同级 specificity 下后者覆盖前者 → 鼠标悬浮选中行完全没变化。
补 `[role=treeitem][aria-selected=true]:hover` 提亮，未选行补 2px `--px-gold-deep`
左条。光标同理：原来的像素手只覆盖 `button/a/select/[role=tab]/[role=menuitem]/[role=switch]`，
`[role=treeitem]` 落到宿主 `cursor:pointer`，于是变回系统自带小手；
补 `[role=treeitem]/[role=option]/[role=button]/[role=link]/[aria-selected]/[aria-current]`，
并让行内非文本子元素 `cursor:inherit !important`（排除输入框/contenteditable）。

**⑦ 纸面主题的 `--px-wood-dark` 等于 sidebar 底色。**
面板导航是 `button.panelRow`，generic button hover 原来用 `--px-wood-dark`；
纸面主题 `--px-wood-dark` 和 `--px-sidebar-fill` 都是 `#E8DCC8`，hover 前后同色，
用户看到的就是「完全没交互」。generic hover 改用 `--px-wood-mid`（与侧栏至少差一档明度）；
当前项 `[aria-current=page]` 也补 wood-mid 底 + 金左条 + hover dither，不能只靠 3px 边。

**⑧ `kbd` 加 2px 边框/内边距会把菜单撑出横向滚动条。**
宿主菜单的快捷键是普通 `kbd`（`Ctrl` `+` `.`），没有固定键帽尺寸。
v1.6.0 的通用 `kbd { border:2px; padding:0 4px }` 让每个键帽变宽，菜单内容超过固定宽度，
底部就出现横向滚动条；同时菜单/dialog 的 2px 边框在 content-box 下再多吃 4px。
现在 `kbd` 只改字体/颜色、不动盒模型；菜单和 dialog 加 `box-sizing:border-box`，
菜单 `overflow-x:hidden`，滚动条从 10px 降到 8px，设置页按钮补 `min-width:0`。

**⑨ `overflow-y:auto` 的 navList 会连带出横向滚动条。**
设置页左导航 `.navList` 只写了 `overflow-y:auto`，按 CSS 规范另一轴 `visible`
会被算成 `auto`；像素字体 + 按钮 min-content 宽一点点，就出现一条横向滚动条。
用 `[role='dialog'] div:has(> button[aria-current])` 精确命中 navList（不碰宿主
hash class），`overflow-x:hidden`；菜单内部的 `_viewport_` 同样会滚动，给
`[role='menu'] *` / `[data-menu-material] *` 统一 `overflow-x:clip`。
另外设置 dialog 的底色就是 wood-mid，通用按钮 hover 也是 wood-mid，等于没变；
dialog 内普通按钮改用 wood-warm。

## #12 真素材 9-slice 的五个坑（v1.7.0，Wood → Hologram）

**① 不要给 tooltip / toast 套大面板框。**
第一版把 `[role=tooltip]` 也切了 10px 面板，悬停“发送消息”时像一块浮动门板。
浮层应该是 2px 细边 + 实底；面板图只给 dialog/menu 这种有明确内容区的容器。

**② 96×32 横条按钮不能塞进方形图标键。**
主按钮素材是横向 plaque；发送键是 36px 方形，硬切后里面只剩 8px。
需要 `button[class*='primary']:has(> svg:only-child)` 单独改用 32×32 `Frame_Lite`。
文本主按钮仍用横条，6px 上下 + 10px 左右是能放下文字的最小边框。

**③ 按钮 32px 高不能按 14px 上下边框切。**
`slice:14` + `border-width:14px` 会把内容区吃到只剩 4px，文字直接消失。
Hologram 继续用 `slice:8 20` + `border-width:6px 10px`。

**④ 只有面板图、没有换底色的主题只是“换皮”。**
Wood 版被用户否掉：「不就是木屋套了个皮吗？」。深棕底 + 奶油框仍属于原 wood 配色。
Hologram 把 base/layer/border/label 全部换到深蓝/青色，面板填充深蓝，
才形成独立风格；素材只是风格的一部分，不是全部。

**⑤ 素材授权与路由必须一起做。**
8 张 Hologram 切片 CC BY 4.0，LICENSE/ATTRIBUTION 随包走；
node 路由 `/dsh-pixel-ui/assets/hologram/*` 白名单，不按任意路径读文件。
旧 Wood 素材已从最终包移除，避免同一主题两份授权。

**附带（预览工具）**：`file://` 下 CSS 里的 `/dsh-pixel-ui/fonts/...` 和
`/dsh-pixel-ui/assets/hologram/...` 绝对路径都加载不到；生成预览时把这两个前缀替换成
`file:///.../assets/...`，否则 headless 截图会误判「素材/字体没生效」。

## #13 第二轮素材主题的六个坑（v1.8.0，Pumpkin + Papernote）

**① 先查授权，再决定打不打包。**
两个包的授权完全不同：Complete UI 的 `License.txt` 明写 CC BY 4.0（可再分发）；
PixelPocketPhoneUI 只有 README 的 © IndigoLay 与字体 OFL，商店页是 Unity Asset Store
「Extension Asset」+ 标准 EULA——**没有随包再分发许可**。
把它的 PNG 打进公开仓库/npm = 再分发原始素材，不能做。用户确认后本版只做包 1；
`TEMP/pixelpocket-ui` 的本地原型不入库。教训：素材包先看 `License.txt`/README，
没有授权文件就当「不可再分发」处理。

**② 素材路由每加一套都要重启；改成构建期内联。**
v1.7 用 `webServer.register` 的 `/assets/hologram/*` 白名单路由。加南瓜灯/便签本时
同一模式要继续动 node 半边，而 desktop 的 node 半边更新必须重启。
改成 `url('pxasset:<theme>/<file>.png')` + `scripts/asset-inline.mjs` 在构建时换
`data:image/png;base64,...`：client 单文件自包含、`dsh-app://` 可用、刷新即生效。
代价：`lib/client.js` 从 ~67 KiB 涨到 ~98 KiB（23 张 PNG），可接受。

**③ `border-image-repeat: stretch` 会把装饰性边框拉变形。**
南瓜的 `frame_full.png` 96×96、30px 切片，横向 `stretch` 后每颗南瓜被拉成椭圆；
改 `round`（平铺并轻微缩放）后南瓜保持形状。
便签本的 `FrameStandard01` 左边是**活页孔**：横向撕边要 `stretch`、纵向孔要 `round`，
所以写 `stretch round`（先水平后垂直）。反过来会把孔拉成长椭圆。

**④ 浅色主题的纸面可能和页面同色，浮层会「消失」。**
`FrameStandard01` 的填充 `#FFF9F1` 与便签本原来的 page `#FDF7EC` 几乎同色，
截图里菜单像是几行悬浮文字。修法两层：
(a) 页面 base 加深到 `#F2E6D2`（`--px-wood-darkest` 与 `--dsw-alias-bg-base` 同步）；
(b) 给 dialog/menu-material 加 2px `outline`（`--pxa-outline`，便签本设为 `#8C5A2C`；
其他素材主题不设即透明），`outline-offset:-2px` 落在素材内缘。
注意不能用 box-shadow——平面临界门禁会拦。

**⑤ 宿主自己画的表面要用 token，不要用类名。**
用户气泡、composer 输入区、弹层菜单、选择键、tip 都是宿主组件画的，颜色来自
`--dsw-specific-bubble` / `-input-major` / `-menu` / `-selector` / `-tip`（默认值是宿主蓝/灰）。
不覆盖这些 token，皮肤再换色，气泡还是现代默认蓝。把它们加进主题表（17→23），
既跟随主题，又避免 `[class*='bubble']` 这种脆弱选择器（也过不了「禁止无前缀 class 子串」门禁）。
`--dsw-specific-bubble-highlight` 一并补上，保持键集完整。
**注意（源码核对）**：`ThemeRuntime.register()` 只负责登记 token；真正写 `body.style` 的是
ui-layout 的 presenter——`host-dsh-client-ui-layout.js:542-544` 直接
`for (const [name, value] of Object.entries(snapshot.active.tokens)) body.style.setProperty(...)`，
**没有 `--dsw-alias-*` 白名单**。所以新增 `--dsw-specific-*` 不需要改宿主，也不会被静默丢弃。

**⑥ 主题 token 键集必须逐个主题一致。**
新增 6 个 token 时最容易只加在新主题上；漏掉的主题会静默回落到宿主值，测试也未必红。
`scripts/test-client.mjs` 现在拿 `pixel-wood` 的键集和其余六套逐一 `deepEqual`，
`scripts/audit-contrast.mjs` 又新增了「label-primary / 气泡、菜单面、输入区」三对，
任何一套漏值都会 MISSING。

**附带（Windows 编辑工具链）**：
- PowerShell 5.1 的 `Set-Content -Encoding utf8` 会**写 BOM**（首字节 `EF BB BF`），
  且双引号字符串里的中文引号（「」）会被当成语法错误；批量改源文件用 Node 脚本 +
  `UTF8Encoding($false)`，或直接用 edit 工具。

  无效 token（这次的 harness 里就留了一行 `\n.dialog-demo …`）。多行拼接用 Node/模板字符串。

**附带（预览）**：`TEMP/preview-v18.mjs` 复用真实的 `asset-inline.mjs` 与真实 CSS，
刻意不复刻构建逻辑，这样预览过的 9-slice 就是产物里的那一份；theme token 从

## #14 主题化光标：笔尖热区 + 基础皮肤的手/文本光标（v1.8.0 实机反馈）

**现象**：便签本主题里，空白处是铅笔，移到按钮/链接或文字上就变回像素手 / I-beam。

**根因（两层，缺一不可）**：
1. `cursor` 虽然是继承属性，但基础皮肤对 `button/a/[role=…]` 写了像素手、
   对 `input/textarea/[contenteditable]` 写了 I-beam，且都是 `!important`；
   主题只在 `body` 上写铅笔，子元素上的更高优先级规则照样生效。
2. 铅笔素材的方向容易看反：`CursorPencil01.png` 的**笔尖在左上 (4,4)**，
   右下红色那块是橡皮。之前热区写 `26 26`，点击/悬停的判定点落在橡皮上，
   视觉和交互错位 20 多像素。

**规避**：
```css
html[data-pixel-theme='pixel-papernote'] body,
html[data-pixel-theme='pixel-papernote'] body * {
  cursor: url('pxasset:papernote/cursor.png') 4 4, auto !important;
}
```
选择器特异性 (0,2,1) 高于基础的 `html[data-pixel-ui] button` (0,1,2)，
`!important` 对 `!important` 时由特异性决胜；用 `body *` 一次覆盖按钮/链接/输入/正文。
验证方式是 CDP 读 computed cursor（headless 截图不画光标），
`scripts/test-client.mjs` 也加了「body * 规则 + 4 4 热区」两条门禁。

**通用教训**：
- 主题想要一种指针贯穿全站，必须显式压过皮肤的交互/文本规则，不能只写 `body`；
- 自定义光标先量 alpha bbox 和笔尖坐标（本图 `getbbox()=(4,4,27,27)`，tip=(4,4)），
  热区错了用户会觉得「点不准」，却很难说清是哪里不对。

## #15 `border` 简写只接受一个宽度，多值宽度必须用 `border-width`（v1.8.1）

**现象**：便签本对话框的标题压在撕边上、按钮文字贴边；CDP 读 computed
`border-top-width: 0px`，但 `border-image` 又正常画出来，内容被边框图盖住。

**根因**：
```css
/* 错误：border 简写的 <line-width> 只取一个值 */
border: 12px 8px 12px 18px solid transparent;
```
CSS `border` 简写的正式语法是 `<line-width> || <line-style> || <color>`，
**一个**宽度；`border-width` 才接受 1–4 值。浏览器在计算期把整条声明判为
invalid-at-computed-value-time 并丢弃，`border-width` 回落到初始值 `0`。
而 `border-image` 简写里的 `/ 12px 8px 12px 18px` 是独立的
`border-image-width`，照常生效——图还在，只是不占布局空间。

受影响的不止 papernote：pumpkin 的 `6px 8px 10px 8px`、hologram 的
`6px 10px` 按钮，以及所有走这套变量的 icon/input/select/dialog/menu 规则。

**规避**：
```css
border: 0 solid transparent !important;
border-width: var(--pxa-panel-width, 24px) !important;
```
`scripts/test-client.mjs` 现在断言 panel/button/input 的 `border-width`
longhand 存在，并禁止素材层出现 `border: var(--pxa-…`。

**通用教训**：用 `var()` 拼简写会把「解析期不报错、计算期整条丢弃」藏起来；
多值宽度一律用 longhand。仅靠视觉截图很难发现——边框图还在画，
只有量 `getComputedStyle().borderTopWidth` 或看内容是否压边才暴露。
