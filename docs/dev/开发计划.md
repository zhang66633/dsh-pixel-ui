## 4. 关键取舍

1. **不打包 PixelPocketPhoneUI**：它的授权只覆盖「在自己的作品里使用」，把原始 PNG 随 MIT 插件公开分发属于再分发。等用户拿到书面许可再按同一流程加。
2. **素材内联而不是继续加路由**：route 方案每加一套素材都要动 node 半边并重启；内联后 client 单文件自包含，`dsh-app://` 也无需绝对 URL。代价是 bundle 从 ~67 KiB 涨到 ~98 KiB（23 张 PNG）。
3. **共用 `--pxa-*` 变量层**：三套素材主题的差异只有图片、切片、边框宽度、重复方式、文字色；规则只写一次，新增主题≈一个变量块。
4. **`border-image-repeat` 按素材挑**：藤蔓要 `round`（保持南瓜形状），活页孔要 `stretch round`（横向撕边拉伸、纵向孔平铺），全息细线可以 `stretch`。
5. **便签页面底色加深一档**：`FrameStandard01` 的纸面几乎与页面同色；把 base 从 `#FDF7EC` 改到 `#F2E6D2`，再补 2px `outline` 墨线，悬浮菜单才看得出是「一张纸」。
6. **宿主表面走 token 不走类名**：`--dsw-specific-bubble` 等由宿主组件直接消费；加 token 比 `[class*=bubble]` 稳，也过得了「禁止无前缀 class 子串」门禁。

# 开发计划 · v1.6.0（像素细节与阶梯动效 pass）

> 状态：**已完成**（2026-10-25）。验收见文末。

## 1. 背景与目标

用户原话：「对目前的像素风格进行优化，细节、动感等，逐一细节优化」。
v1.5.0 已经做到「完全平面」，但动效只有按钮的 60ms 过渡，很多组件没有状态反馈；
同时宿主的思考 shimmer、spinner、toast 仍是平滑动画，和像素语言不一致。

拆成四类：

| # | 目标 | 判定标准 |
| --- | --- | --- |
| A | 动效语言统一 | 所有新动效只用 `steps()`、离散帧或 sprite 位移；不出现 `transition: all`、不动物理尺寸 |
| B | 组件细节 | 按钮/页签/输入/选择件/代码块/表格/吸顶标题/标签/菜单/toast/dialog/tooltip 逐项有像素化状态 |
| C | 宿主状态语言 | 思考中、运行中、spinner、toast 四类宿主状态改为阶梯动效 |
| D | 无障碍与回归 | `prefers-reduced-motion` 连伪元素一起关；`npm test` 与对比度全绿；真实主题预览四套可看 |

## 2. 动效状态机

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Hover: pointer
    Hover --> Pressed: pointerdown
    Pressed --> Idle: pointerup
    Idle --> Selected: click
    Selected --> Idle: 再次点击/切走
    Idle --> Thinking: 请求发出
    Thinking --> Running: 工具开始
    Running --> Idle: 完成/失败
    Idle --> Toast: 状态变化
    Toast --> Idle: 3–5s / 关闭
```

所有边的视觉时长只有三档：`80ms`（press/hover）、`140ms`（tab/nav）、
`220ms`（toast/dialog）。超过 220ms 的一律是循环状态（思考/运行/spinner），
用 `steps()` 保持离散。

## 3. 关键设计决策（为什么）

1. **主按钮改 token，不只改 class**：宿主 `_primary_` 用
   `--dsw-alias-button-primary-fill` / `-hover` / `--dsw-alias-label-primary-foreground`。
   把这 3 个 token 加进四个主题，宿主所有主按钮（发送、确认、安装）自动跟随主题；
   CSS 再兜一层 class 规则，防止第三方按钮没走 token。
2. **页签下划线用 `::after` + `scaleX`，不用 `background-size`**：
   `background-size` 在透明 border 上会留下一条缝（v1.6 第一版实测），
   `::after` 定位到 `bottom:-3px` 正好盖住 3px 透明 border，和分隔线齐平。
3. **shimmer 的 2px 光标用 `background-image`，不用 `border-left`**：
   宿主的 decoration 是绝对定位的复制文本，加 border 会把复制文本右移 2px，
   出现「重影」。background 不参与布局。
4. **勾/点用 CSS 变量 `--px-check` / `--px-radio`**：纸面主题的深金底上，
   深木色勾只有 2:1 左右，肉眼几乎看不见；变量让纸面换成纸白勾，其余主题保持深勾。
5. **reduced-motion 必须管伪元素**：`html[data-pixel-ui] *` 管不到 `::before/::after`，
   第一版探针发现 tab 下划线在 reduced 下仍有 140ms 过渡；补 `*::before/*::after` 后归零。
6. **不做「处处动」**：动效只出现在有因果的位置（按下、选中、运行、到达），
   静态纹理（斑马纹、dither、角标）不循环动画。

## 4. 验收标准（全部达成）

- [x] `npm test`：compat 23 + host 20 + client 28 + contrast ALL PASS
- [x] 浏览器探针：tab `steps(4)`、shimmer `steps(1)`、toast `steps(3)`、running `steps(2)`、spinner `steps(8)`
- [x] `--force-prefers-reduced-motion` 探针：tab transition `none`，shimmer/toast/running animation `none`
- [x] 四套主题静态预览（`TEMP/preview-pixel-*.png`）无溢出、无白块、勾/点可辨
- [x] README / 迭代 / 踩坑 / 计划同步

## 5. 未验证 / 下一步

## 3. 关键设计决策（为什么）

1. **列宽修在皮肤里，而不是改宿主**：`--dsh-chat-content-width` 的 clamp 下限是宿主
   刻意给窄屏留的设计值，皮肤只在**宽屏**把它撑开（`clamp(680px, 64vw - 140px, 1200px)`），
   1281px 视口下算出来仍是 680px —— 不改变宿主的窄屏观感。
2. **用 `!important` 声明自定义属性**：宿主会把 `--dsh-chat-user-width` 以内联样式写在
   容器上；自定义属性参与级联，`!important` 是唯一能压过内联的手段。已用
   `TEMP/cssvar.html`（headless Edge 截图）验证过这条级联行为。
3. **偏好走 index 注入而不是加绝对 URL**：桌面端 renderer 不知道宿主 HTTP 端口
   （`location.origin` 是 `dsh-app://app`），注入是两条部署（desktop / web）都存在的
   通道，而且**在首屏前就绪**，顺带消掉闪现代皮的一帧。
4. **完全平面**：见踩坑 #6。用户明确要平面，因此把「层次」从阴影改成
   描边 + 明度差 + 2px 抖动 + 手绘 SVG；同时立一条测试门禁，防止以后又长回阴影。
5. **`restoring` 标志提前放掉**：皮肤恢复是异步的（要读偏好），而宿主的初始
   preference 会在同一窗口到达；标志必须绑定「皮肤已应用」而不是「读取已完成」。

关键设计决策（为什么这样做）：

1. **peer 范围不用 `workspace:*`**：app-boot 的 `evaluatePluginCompatibility` 只认 `peerDependencies` 里 `@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` 的范围（`semver.satisfies(运行时, 范围, {includePrerelease:true})`）。`workspace:*` 虽被支持，但写成显式多段范围与 cost-meter 1.7.49 生态惯例一致、可读性更好。范围同时覆盖 `0.1.0-rc.6~0.1.7-rc.2` 与 `0.2.0-rc.1~0.2.x`（已用 semver 实测 5 个运行时全过）。
2. **`dsh.compatibility.dshReleases` 仍然写**：app-boot 不读它（源码无匹配分支），但它是 dshmarket/仓库的声明式惯例，向下游说明「哪些版本实测过」。
3. **偏好持久化放宿主文件，不做成设置 schema**：`ThemeRuntime.setTheme` 只把内置偏好（light/dark/system）写进宿主 settings scope，第三方主题 id 写不进去（`isThemePreference` 门槛）。所以自建 `$DSH_HOME/storages` 文件 + 同源路由，浏览器侧 localStorage 做每 origin 镜像。旧宿主（无此路由）GET 返回 404 → 客户端降级为纯 localStorage，行为与 v1.3.0 一致。
4. **恢复顺序先本地后宿主**：本地镜像同步生效避免闪烁；本地缺失（新端口）才等一次 GET；两侧都有且不一致时以宿主为准（宿主是「最后一次选择」的权威）。

## 3. UI/UX 重构要点（依据 ui-ux-pro-max 检索结论）

检索过的规则（scripts/search.py，domain=ux）：对比度 4.5:1 / 非文本 3:1；web 目标 ≥24 CSS px（WCAG 2.2）；焦点环必须可见且不遮挡；reduced-motion 必查。

| 项 | v1.3.0 | v1.4.0 |

| 对比度 | 14 处不达标（浅色主题金色系 1.2~2.2:1） | 审计脚本门禁，全绿；金色系按明/暗主题拆成对变量 |
